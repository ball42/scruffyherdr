# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

scruffyherdr is a layout and mods for Herdr (a desktop agent multiplexer): Herdr mods, ten scene themes and pictures, and Claude Code hooks. README.md is the user-facing spec (features, config keys, key bindings, install flags); keep it in step with behaviour changes.

## Commands

```sh
npm test
bash tests/install.test.sh
```

One test file, or one test by name:

```sh
node --test tests/grid.test.js
node --test --test-name-pattern="summary picks" tests/
```

`tests/scrub.test.js` keeps personal strings (home paths, hostnames, private IPs, names) out of every tracked file's text and name, and metadata out of the pictures and SVGs. Rename the string; never add an allow-list entry. The one exception is built into the pattern: the account name as the repo's own path (`<owner>/scruffyherdr`, the README's clone URL).

`./install.sh` symlinks `herdr/*` into `~/.config/herdr-app/` (Herdr reloads a mod when one of its files is saved, so edits apply live; a `git pull` doesn't count as a save, so install.sh touches each mod's `main.js` to reload it); `--check` and `--uninstall` are documented at the top of the script. New mod folders and themes load only on Herdr restart, and so does glyph art in `glyphs/` (outside `mods/`): install prints `restart Herdr to load new glyph art` once when a glyph link, or the file behind one, changed since the last install.

`herdr/` is also the Herdr gallery folder (herdr.dev/layouts): `herdr/layouts/scruffy.json` and `herdr/keys.json` are generated by `node scripts/make-layout.js --gallery` and `--gallery-keys` (build from `tests/fixtures/herdr-0.1.15-main.json`, never hand-edit; `tests/gallery.test.js` fails on drift), beside `herdr/RECIPE.md` and `herdr/preview.png`. install.sh never links those four. A change to the layout, its look or the kit keys means regenerating them.

`install.sh` runs `private/install.sh` last when that file exists, so a personal overlay can add its own mods, settings, keys and picture or glyph overrides without forking the core. The core names nothing in it.

## Herdr mod runtime

Herdr's mod API reference lives outside the repo: `~/.config/herdr-app/AGENTS.md`, `herdr.d.ts`, `gpui-kit.d.ts`. Read them before using an API you haven't seen in this repo.

- Mods import from `herdr`, `gpui-kit`, `gpui-base` and their own folder only. The runtime lacks Node globals (`setTimeout`, `process`, `Buffer`, `structuredClone`, ...): use `cx.timer` instead. `tests/globals.test.js` enforces the banned list.
- A mod can't import from another mod's folder, so `look.js` is copied into `kit-rail`, `kit-tabs`, `kit-pane` and `kit-scenes`. **kit-rail's copy is the source**: edit it, then copy it over the others (`tests/look.test.js` fails on drift).
- Herdr's shipped layouts reject structural edits, so `scripts/make-layout.js` generates the one layout, `scruffy`, from Herdr's `main.json` on every install (it imports `gridLayout` from the mod). The scene and the view live inside it: `herdr-signals` swaps the dressed tree (theme pair, picture, glass) and the focus or grid body in place. Scenes are listed in `herdr-signals/scenes.js`; `merge-config.js` and `install.sh` read that list, and `look.js`'s `TONES` keeps each scene's needs-you colours and glyph under the same keys, which `tests/scenes.test.js` checks. Panel sizes are kept per view in `~/.config/herdr-kit/sizes.json`, and the undressed focus tree in `layout-focus.json`. Install migrates off older layout names (`LEGACY_LAYOUTS`) and deletes their files only after a verified switch.
- `<mod>.<command>` reaches only shown copies of a mod, and a mod copy starts only when its block first shows.

## Architecture

**`herdr-signals` is the brain; the `kit-*` mods only draw.** Each poll, `herdr-signals/main.js` reads Herdr's agents, resolves names, and publishes a view model with `setShared("herdr-kit")`. `kit-rail` (urgency rail), `kit-tabs` (tab bar) and `kit-pane` (pane / grid tile header) render from `shared("herdr-kit")`. `kit-scenes` is a dialog overlay: the scene picker (opened by `herdr-signals`' `scenes` command, `cmd-shift-s` or the strip's `◐ <scene>`) that draws the `kit.scenes` list herdr-signals publishes at start (pictures in `herdr/backgrounds/thumbs/`, made by `scripts/thumbs.py`) and sets `kit.sceneWant` on a pick; its cursor logic is `kit-scenes/picker.js`. The strip drops words before it clips its right-hand buttons (`herdr-signals/strip-fit.js`). Cross-mod UI state also travels through shared keys: `kit.grid`, `kit.gridAll`, `kit.spotlight`, `kit.gridFocus`, `kit.pins`, `kit.snooze`, `kit.runsDismissed`. Add-on mods (listed in config `addons`) publish `kit.addon.badges`, `kit.addon.rows` and `kit.addon.buttons`, and watch `kit.addon.press`; the core draws them and holds no add-on logic (`docs/addons.md`).

Inside `herdr-signals`, `main.js` is the only file touching herdr globals or I/O. The rest are pure functions with unit tests in `tests/`: `model.js` (view model, attention, urgency order), `names.js`, `grid.js`, `card.js` (Discord away card), `policy.js` (strip counts), `idle.js`, `folder.js` (which names files to reread), `layout.js` (has Herdr's main layout moved on since install), `scenes.js` (the scenes' theme pairs and pictures, and the legacy layout names install migrates off), `wallpaper.js` (the night or day picture, swapped as the theme turns light or dark), `glass.js` (the glass sidebar and bars, tinted with the scene's `panel` colour), `addons.js` (the add-on contract). Put new logic in a pure module with a test, and wire it from `main.js`. View code (`look.js`) is tested by `tests/support/gpui-stub.js`, which stubs gpui and gives a fake `cx` with a manual clock.

Data flowing in and out of the mod:

- **Context:** `claude/ctx-tap.mjs`, fed the status line's JSON, writes `~/.config/herdr-kit/ctx/<HC_TERMINAL_ID>` (percent left). It must always exit 0 and print nothing. `claude/statusline.mjs`, the status line install sets (it saves the old one in `statusline-prev.json`), does the same write through `ctx.js`'s `writeCtx`, then runs the old line; it always exits 0.
- **Names:** `claude/name-hook.mjs` is a Claude Code hook (installed into `~/.claude/settings.json` by `scripts/merge-config.js`) that writes `~/.config/herdr-kit/names/<HC_TERMINAL_ID>.json` with the session's `/rename` name, title, question, tool and context use. `herdr-signals` watches that folder. The hook must always exit 0.
- **Discord:** one webhook card per stretch away, edited in place (`card.js`).
- **Config:** `~/.config/herdr-kit/config.json`, outside the repo (it can hold a webhook). A new config key needs a default in `main.js` `DEFAULTS`, `config.example.json`, and the README Config table.

`scripts/merge-config.js` edits files the kit doesn't own (`~/.claude/settings.json`, Herdr's `keys.json`): it touches only its own entries, backs up first, leaves a user's conflicting binding alone, and skips malformed JSON. Keep that contract.

## Conventions

- Colour-blind-safe states: orange (`#ec8e2c`) = needs you, blue (`#58a6ff`) = done, never red against green, and every state also carries a glyph or word. On a light theme they become `#b35900` and `#0969da`. Needs-you follows the scene: Endor's is firefly gold (`#f2c14e` / `#8a6400`) with a fir-and-fireflies glyph in place of the twin suns. Mods call `useTheme(theme(), shared("layout"))` at the top of render and use look.js's `ORANGE` (the needs-you colour, whatever its hue) / `BLUE` / `INK`, never hex; grid borders take `spec.light` and `spec.scene`, and the scene colours live in look.js's `TONES` and `scenes.js`'s `needs`.
- `install.sh` must stay Bash 3.2 compatible (macOS default).
- Adding a scene: a theme pair in `herdr/themes/`, a night and day picture (a Pillow script in `scripts/`, the day one mid-tone so it shows through the terminals), a `SCENES` entry in `scenes.js` (themes, pictures, `needs` colours, strip `asks` glyph), a `TONES` entry in `look.js` (copied to kit-tabs, kit-pane and kit-scenes) with a glyph function in `GLYPHS`. A glyph can be drawn from layer files instead (`glyph: "layered"`, as Small Moon's is): `herdr/glyphs/<scene>-body.svg`, `-edge.svg`, `-light.svg` and `-mover.svg`, 14 by 14 and one colour, linked per file into Herdr's `glyphs/`; look.js names only the files (`glyphLayers`), never what they draw. Run `python3 scripts/thumbs.py` and commit the new `herdr/backgrounds/thumbs/` pictures for the picker. Check it in the real window with `herdr-app shot` before merging.
- Pictures are original art. Don't copy a film's distinctive designs; the scrub can't see pixels, so look at every picture before committing it.
